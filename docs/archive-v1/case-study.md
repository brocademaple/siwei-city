# 思维城邦 Case Study

## 背景与问题

用户经常带着一个模糊 idea 进入 AI 工具，但离开时只得到一段回答，缺少结构、取舍和行动。思维城邦尝试把 AI 生成能力放进一个更可控的思考系统：观点被建筑化，关系被道路化，多 agent 被组织成居民圆桌，结果被卷轴馆沉淀。

## 用户画像

- 准备面试或作品集的产品经理：需要展示产品判断、结构化思考和 AI 产品意识。
- 有复杂议题的创作者/学习者：需要从灵感推进到可执行方案。
- AI 工具重度用户：希望 AI 不只是回答，而能参与长期讨论和复盘。

## 核心场景

1. 用户输入一个模糊议题。
2. 用户选择探索、决策或行动模式。
3. 系统生成初始观点地图和居民圆桌回合。
4. 用户预览 agent 来函，选择是否采纳入城。
5. 巡城官指出结构缺口，并转化成下一步修缮任务。
6. 卷轴馆导出结构化 Markdown，并保存历史城邦。

## MVP 范围

已实现：

- React + Vite Web 原型。
- 古希腊/罗马城邦视觉隐喻。
- 三种固定讨论模式。
- 本地模板回退与 Mimo API 代理接口。
- 城邦账簿展示 token、调用次数和估算费用。
- 圆桌来函预览与采纳入城。
- 巡城官令与修缮动作。
- 卷轴馆 Markdown 导出、样例馆藏、历史城邦本地保存。

未纳入第一版：

- 移动端适配。
- 账号体系和云端同步。
- 真正长上下文多轮 agent 编排。
- 图片级别的新建筑定制资产。

## 信息架构

- 左侧：立题台、模式选择、账簿、建筑工坊。
- 中央：城邦地图、观点建筑、道路、服务建筑。
- 右侧：服务抽屉，包括居民席位、巡城官塔、卷轴馆。
- 本地存储：当前会话与历史城邦。
- 远端接口：Vercel Serverless Function 代理 Mimo API。

## AI 交互原则

- 来源透明：本地模板、AI 生成、用户手写分别标记。
- 成本透明：展示调用次数、输入/输出 token、估算费用和失败原因。
- 用户掌权：AI 发言不自动改图，必须采纳后才入城。
- 结构优先：AI 生成内容必须进入问题、假设、证据、反驳、行动等结构。

## 关键取舍

- 先做桌面 Web，而不是移动端：因为首要目标是面试展示和复杂信息操作。
- 先做固定三模式，而不是完全自由 agent：降低新手学习成本，也便于验证流程质量。
- 先用 localStorage 保存历史城邦：快速验证“多项目归档”是否有价值，再考虑账号同步。
- 先用现有建筑素材复用服务建筑：保证功能完整，后续再补更精细的卷轴馆/席位/高塔资产。

## 下一步路线图

1. 接入真实 Mimo API，并验证 usage 返回与费用估算。
2. 让 agent 读取完整上一轮圆桌记录，产生更明确的互相引用和回应。
3. 给每条道路增加“关系解释”字段。
4. 为卷轴馆、蜡板任务卡、居民席位生成专属美术资产。
5. 增加多城邦搜索、标签和云端同步。
6. 增加面试展示模式：一键生成项目介绍、PRD、测试报告和演示脚本。
