# 思维城邦版本历史

## 2.0：古希腊城邦议会主舞台

2.0 把产品主体验重新锁定为一条清晰 MVP 路线：

```text
城邦主页 -> 冲突议会 -> 居民圆桌 -> 用户采纳 -> 巡城塔诊断 -> 行动码头远航 -> 大图书馆归档
```

核心变化：

- 主页从观点卡片堆叠改为可缩放、可拖拽的古希腊城邦世界地图。
- 首页只保留 8 个已定义建筑：冲突议会、大图书馆、居民区、假设码头、行动码头、沉思庭院、记忆墓园 / 废案馆、灯塔 / 巡城塔。
- 主要交互集中到议会大厅，居民发言、观点碰撞、采纳、巡城和卷轴都围绕议会展开。
- 居民角色从早期功能入口升级为 prompt 人格：有性别多样性、不同职责、人设、语气和输出契约。
- 每个建筑都有二级场景和用途说明，但深层机制暂时保持轻交互，避免分散 MVP 主线。

## 1.0：观点建筑地图迭代日志

1.0 验证的是最初产品假设：复杂思考可以被空间化。

当时的核心结构：

- 用户输入模糊议题。
- 系统生成问题、假设、证据、反驳和行动。
- 每条观点成为地图上的建筑。
- 道路表达支持、冲突、依赖、延伸和回流。
- 角色建议以居民来函形式出现，用户采纳后才入城。
- 巡城官令诊断结构缺口。

1.0 的价值：

- 证明“观点建筑 + 道路关系”比普通列表更有产品记忆点。
- 留下了旧 panorama、建筑、城区和纹理资产，可以继续用于迭代日志、说明书和对比复盘。
- 梳理出早期地图编排思路：建筑承载观点，城区暗示职能，道路解释观点关系。
- 暴露了主页复杂度问题：当地图上同时出现太多建筑和卡片，用户不知道第一步该做什么。

## 为什么需要 2.0

2.0 继承 1.0 的空间隐喻，并把它收束成更清晰的游戏化路径：

- 首页只回答：点哪里开始。
- 议会只回答：这轮讨论下一步做什么。
- 其他建筑只回答：它在议题闭环中负责哪一段。

因此，1.0 只作为 GitHub Pages 的迭代日志保留；2.0 作为正式项目和当前主应用入口。
