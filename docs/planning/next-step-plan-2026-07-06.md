# 思维城邦下一步计划

日期：2026-07-06

## 这次资料包说明了什么

`siwei-city-dialogue-package-2026-07-06.zip` 是一次产品设计交接包。它补齐了文档索引、文化背景研究和资料来源索引，并把“冲突议会”的下一步方向从普通多角色建议，推进到“有讨论协议的居民圆桌”。

核心判断：

- 当前 MVP 已经可运行，主链路是输入议题、开局推演、观点建筑、居民建议、采纳入城、道路关系、巡城官令和卷轴导出。
- 下一步最值得做的不是扩很多新建筑，而是把议会大厅做深，让每轮发言拥有协议、回应对象和可审计的论证动作。
- 文化背景材料可以落成 5 个产品协议：问志开局、苏格拉底反诘、亚里士多德论题拆解、先秦类比游说、名实校准。
- 这些协议应该先以本地模板和结构化数据落地，再接入真实 AI agent，避免 API 联调掩盖产品机制是否成立。

## 推荐下一阶段目标

下一阶段目标：做出“协议化圆桌 v0.3”。

用户输入一个议题后，系统先根据议题和讨论模式推荐一种讨论协议；居民发言不再只是建议列表，而是带有 `argumentMove`、`respondsTo`、`suggestedProtocol` 和可采纳地图变化的结构化记录。巡城官令也要能指出“缺口类型”和“下一步适合使用的协议”。

## P0：协议化圆桌数据层

目标：先让现有本地逻辑能表达讨论协议，不改大 UI。

建议改动：

1. 在类型层增加 `DiscussionProtocol` 和 `ArgumentMove`。
2. 给圆桌发言增加字段：协议、论证动作、回应对象、建议道路、可采纳节点类型。
3. 在 `src/lib/opening.ts` 或新的 `src/lib/protocols.ts` 中实现本地协议选择。
4. 更新 seed 数据，让默认议题能跑出一轮带协议的示例。

验收标准：

- 默认议题能生成至少一种协议说明。
- 每条居民发言都能说明自己是定义、追问、例证、反例、类比、利害、行动或修辞改写。
- 原有“预览 -> 采纳入城”流程不被破坏。

建议验证命令：

```bash
npm run build
npm run trace:thinking
```

## P1：巡城官令升级

目标：让巡检从“发现问题”升级为“指出应该用什么讨论协议修”。

建议改动：

1. `src/lib/review.ts` 的 finding 增加 `gapType`：定义、证据、反例、行动条件、听众表达、名实一致。
2. 每条 finding 增加 `suggestedProtocol`。
3. ReviewPanel 展示协议建议，并允许用户把它作为下一轮圆桌的启动条件。

验收标准：

- 缺证据假设会建议论题拆解或墨家式验证。
- 定义含糊会建议名实校准。
- 行动未闭环会建议行动协议或利害回看。

建议验证命令：

```bash
npm run build
npm run test:smoke
```

## P2：卷轴报告升级

目标：让导出的报告能保留“本轮怎么讨论出来”的过程。

建议改动：

1. 报告中加入本轮采用的讨论协议。
2. 报告中加入关键名词定义和定义分歧。
3. 圆桌记录按“发言者、回应对象、论证动作、采纳结果”输出。
4. 行动计划中加入回看指标和证据回流对象。

验收标准：

- 导出的 Markdown 不只是观点摘要，还能解释判断路径。
- 用户可以把报告复制给自己、团队或文章草稿继续使用。

## P3：真实 Mimo / agent 接入

目标：在协议数据结构稳定后，再把本地模板替换为真实模型生成。

建议顺序：

1. 先验证 `api/mimo/chat.ts` 的真实 API、usage、错误结构和费用估算。
2. 用协议化 prompt 让 agent 输出结构化 JSON。
3. 保留本地模板回退。
4. 所有 AI 建议继续先预览，用户确认后才入城。

验收标准：

- API 成功时生成结构化发言。
- API 失败时完整演示路径仍可跑通。
- 账簿能说明本轮是 AI 推演、本地模板还是回退。

建议验证命令：

```bash
npm run dev
npm run verify:mimo -- --url=http://127.0.0.1:5173/api/mimo/chat
```

## 暂缓事项

- 账号、云端保存、多人协作。
- 大量新增建筑入口。
- 把所有非议会建筑一次性做深。
- 在协议数据结构稳定前重写 UI。

## 第一周可执行清单

1. 合入本资料包中的文档入口、文化背景和参考资料索引。
2. 新建 `src/lib/protocols.ts`，定义协议选择和论证动作。
3. 更新圆桌数据类型和 seed 发言。
4. 让 ReviewPanel 显示协议和论证动作。
5. 更新 trace 输出，确认两条公开链路包含协议字段。
6. 跑 `npm run build`、`npm run trace:thinking`、`npm run test:smoke`。

## 关键假设

- 下一步的主要目标是提升核心讨论质量，而不是扩展 SaaS 基础设施。
- 当前文档包中的文化研究先作为产品机制灵感使用；公开精确引用前仍需按 `reference-sources.md` 复核。
- 当前仓库仍以本地可运行 MVP 为主，真实 AI 接入必须保留本地回退。
