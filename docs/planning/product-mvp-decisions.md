# 思维城邦 MVP 产品决策记录

## 用户已确认的方向

### 最终产物

思维城邦的 MVP 不只输出单点答案，而是同时保留三类产物：

1. 一张结构化思维地图。
2. 一个明确的下一步行动。
3. 一份可导出的讨论 / 决策报告。

这意味着界面不能只追求“漂亮地图”，还必须让用户知道当前讨论如何收束、如何行动、如何复盘。

### 第一次输入

用户第一次输入既可能是：

- 一个模糊议题。
- 一堆零散想法。

因此“立题台”应支持两种启动方式：短议题输入和多条想法导入。当前 MVP 先用一个文本框承载，后续可拆成“议题模式 / 想法模式”。

### 居民 / agent 的作用

居民不应该只是一次性给建议，而应该承担两层职责：

- 持续辩论和互相回应。
- 分工协作：研究者找证据，怀疑者找反例，执行者给行动。

当前本地 seed 先模拟四类角色建议；后续应加入“居民互相回应”的时间线或回合制状态。

### 巡城日志

巡城官令的首版职责是“只提示问题”，不自动修改地图。

它应该指出：

- 哪些假设缺少证据。
- 哪些反驳还没有进入议程。
- 哪些观点孤立。
- 哪些行动没有回流证据。

用户仍然保留最终判断权。

### 右侧居民动态 / 巡城日志形态

目标方向是：保留角色头像，但逐步从固定右侧边栏迁移到地图上的“居民席位 / 巡城官塔”。

更理想的形态：

1. panorama 地图上出现居民席位和巡城官塔。
2. 点击席位或塔，展开来函 / 修缮令。
3. 右侧边栏逐步退化为临时抽屉或可折叠日志。

## 立刻影响当前界面的设计原则

- 地图中央只保留关键地点名、观点建筑和观点铭牌。
- 地点解释性文字不常驻显示，改为 hover 小弹窗。
- 居民来函点击只预览，不自动入城。
- 巡城官令点击只定位，不自动修复。
- 指引模式必须让用户看清被指引的画面，而不是把画面全部磨糊。

## 下一阶段建议

1. 在地图右上或广场边缘加入“居民席位”建筑。
2. 在地图边缘加入“巡城官塔”建筑。
3. 点击这两个建筑时，用地图内浮层替代当前右侧长列表。
4. 增加“收束报告”按钮：把当前议题、观点建筑、道路关系、巡城问题和下一步行动汇总为报告。
