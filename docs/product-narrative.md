# 为什么做思维城邦

## 问题背景

AI 时代，信息生成越来越便宜，但复杂思考并没有因此自动变轻。很多用户的真实困难不是“写不出一段内容”，而是：

- 一个模糊想法很难变成可讨论的问题。
- 观点、证据、反驳和行动混在一起，难以判断下一步。
- Chat 类工具给出答案后，讨论过程很快消散，无法沉淀成可复用结构。
- 白板工具自由度很高，但需要用户自己设计思考方法。

思维城邦要解决的是：把模糊议题变成一个可争辩、可修缮、可归档的思考空间。

## 目标用户

- 产品经理：需要做需求判断、方案取舍、面试项目复盘和复杂议题拆解。
- 独立创作者：有很多内容/商业 idea，但需要把想法推进成行动计划。
- 研究型学习者：希望把资料、反驳、假设和结论放进同一张结构图里。
- AI 产品探索者：关注多 agent 如何参与真实思考，而不是只生成一段回答。

## 核心洞察

复杂思考不是线性写作，更像一座城市：

- 问题是城门，决定讨论从哪里进入。
- 假设是议事厅，承载当前判断。
- 证据是港口，把外部事实运进来。
- 反驳是斗技场，让观点经历冲突。
- 行动是工坊，把思考变成下一步实验。

当观点被空间化，用户更容易看见“我缺什么”“哪里冲突”“下一步该走哪条路”。

## 为什么用城邦隐喻

城邦隐喻不是装饰，而是信息架构：

- **建筑**：把观点变成可定位、可点击、可采纳的对象。
- **道路**：把支持、冲突、依赖、延伸、回流关系显性化。
- **居民**：把 agent 角色拟人化，让不同思考职能进入同一个世界。
- **巡城官塔**：把结构问题转成修缮任务，而不是只给诊断文本。
- **卷轴馆**：把讨论结果沉淀为 Markdown 报告、行动计划和历史档案。

## 为什么多 agent 适合复杂思考

复杂议题需要不同认知姿态，而不是单一“万能助手”：

- 研究者负责补证据。
- 怀疑者负责找反例。
- 实践者负责放回真实场景。
- 执行者负责收束行动。

多 agent 的价值不是增加回答数量，而是让观点经历不同角色的交叉检验。思维城邦把这些角色固定成圆桌流程，并保留用户的最终采纳权。

## 产品定位

思维城邦不是普通笔记，也不是单轮 AI Chat。它更像一个“结构化思考工作台”：

1. 输入一个模糊议题。
2. 选择探索、决策或行动模式。
3. 居民圆桌生成多角色回应。
4. 用户采纳有价值的来函入城。
5. 巡城官指出结构缺口。
6. 卷轴馆导出报告、行动计划和历史城邦。

## 当前边界

- 第一版聚焦 Web 桌面端。
- AI 内容默认不自动改图，必须由用户采纳。
- Mimo API 通过 Vercel 代理调用，前端只展示成本和来源，不保存密钥。
- 历史城邦先存在浏览器 localStorage，账号同步后续再做。
