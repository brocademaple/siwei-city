# 思维城邦项目进度与 PRD 概览

更新时间：2026-06-06

## 一句话介绍

思维城邦是一款“把思考变成地图”的前端 MVP。用户输入一个模糊议题或零散想法后，系统把内容拆成问题、假设、证据、反驳和行动，并在一张城邦地图上用建筑和道路呈现推理结构。

## 当前项目状态

结论：项目已经进入“可运行 MVP 原型”阶段，不是空项目，也不是纯静态展示页。

当前已经具备：

- 可本地启动的 Vite + React + TypeScript 应用。
- 可生产构建的 `dist/` 产物。
- 完整的主界面布局：左侧立题/建造，中间城邦地图，右侧角色建议与巡检。
- 本地 seed 数据驱动的默认体验。
- 基于用户输入的本地开局推演。
- 可点击观点建筑、地图内弹窗、道路关系创建。
- 多角色建议的“预览 -> 采纳入城”流程。
- 巡检规则：缺证据假设、未处理反驳、孤立观点、未闭环行动。
- 新手指引和 MVP 任务线。
- 项目内置美术资产、素材切片脚本和绿幕检测脚本。

当前还未具备：

- 真实 AI agent 接入。
- 用户账号、云端保存、多人协作。
- 数据库或本地持久化方案，除新手指引完成状态写入 `localStorage` 外，观点数据刷新后会回到 seed 状态。
- 报告导出功能。
- 结构化导入多条想法。
- 自动化单元测试、端到端测试。
- 地图内居民席位 / 巡城官塔形态。

## 目标用户

首版目标用户是需要把复杂问题“想清楚并推进下一步”的个人创作者、研究者、产品经理、独立开发者或知识工作者。

典型场景：

- 想整理一个还没想清楚的长期问题。
- 做产品方向判断，需要同时保留假设、证据、反对意见和行动。
- 需要把 AI 生成内容转化为自己的判断结构，而不是只收藏答案。
- 想把一堆零散想法收束成下一步实验。

## 产品定位

思维城邦不是传统笔记工具，也不是普通思维导图。它更像一个面向议题的“推理工作台”：

- 笔记工具偏记录，思维城邦偏推进。
- 思维导图偏层级，思维城邦偏论证关系。
- AI 问答偏答案，思维城邦偏保留判断过程。
- 看板工具偏任务，思维城邦偏从观点到行动的闭环。

## MVP 用户流程

1. 用户在立题台输入一个模糊议题。
2. 点击“开局推演”。
3. 系统生成第一批观点建筑：核心问题、可验证假设、证据缺口、主要反驳、最小行动。
4. 用户点击建筑，在地图内查看铭文。
5. 用户用“铺设道路”建立观点之间的支持、冲突、依赖、延伸或回流关系。
6. 用户查看角色来函，预览实践者、研究者、怀疑者、执行者的建议。
7. 用户选择有价值的建议，点击“采纳入城”，让它变成正式观点建筑。
8. 巡城官令诊断当前地图结构缺口。
9. 用户根据巡检结果补证据、回应反驳或推进下一步行动。
10. 后续版本导出讨论/决策报告。

## 当前功能清单

### 立题台

- 输入当前议题。
- 点击“开局推演”后生成新一轮地图。
- 空输入时回退到默认议题。

### 建筑工坊

- 新建观点。
- 支持五类观点：问题、假设、证据、反驳、行动。
- 根据类型自动落入对应城区。

### 城邦地图

- 展示城区、观点建筑、观点铭牌。
- 点击建筑打开详情弹窗。
- 双击建筑或在弹窗中设为道路起点。
- 选择另一个建筑完成连线。

### 道路关系

支持五类关系：

- 支持
- 冲突
- 依赖
- 延伸
- 回流

### 角色席位

当前用本地 seed 模拟四类 agent：

- 实践者：补充工作流和现实证据。
- 研究者：提出结构化判断和理论假设。
- 怀疑者：提出反例、风险和约束。
- 执行者：收束为可操作下一步。

### 巡城官令

当前只提示问题，不自动修复：

- 假设缺少证据支撑。
- 反驳尚未进入议程。
- 存在孤立建筑。
- 行动还没有回流证据。

## 关键文件说明

- `src/App.tsx`：应用主状态，包括议题、观点、道路、选中节点、角色建议采纳状态和新手指引状态。
- `src/data/seed.ts`：默认议题、城区配置、初始观点、初始道路、角色建议。
- `src/lib/opening.ts`：根据用户议题生成第一批观点和初始道路。
- `src/lib/review.ts`：巡检规则。
- `src/components/CityMap.tsx`：地图、建筑和道路渲染。
- `src/components/MapPopover.tsx`：建筑详情和角色建议预览。
- `src/components/IdeaPanel.tsx`：立题台、建筑工坊、左侧角色入口。
- `src/components/ReviewPanel.tsx`：右侧角色席位和巡城官令。
- `src/components/GuideOverlay.tsx`：首次进入新手引导。
- `scripts/check-green-artifacts.mjs`：检测正式美术资产是否残留明显绿幕像素。

## 下一阶段优先级

### P0：补齐 MVP 闭环

1. 增加“生成报告草案”按钮。
2. 报告包含当前议题、观点列表、道路关系、巡检问题、下一步行动。
3. 支持复制 Markdown 或下载 `.md`。

验收标准：

- 用户完成一轮地图整理后，可以直接拿走一份结构化报告。
- 报告不依赖后端即可生成。

### P1：增强输入与持久化

1. 支持多条零散想法导入。
2. 增加浏览器本地保存和恢复。
3. 支持重置当前城邦。

验收标准：

- 刷新页面后地图不丢失。
- 用户可以从一段多行文本生成多个候选观点。

### P2：真实 agent 化

1. 把本地角色建议替换或扩展为真实 AI 调用。
2. 每个 agent 根据当前地图上下文生成建议。
3. 保持“只预览，不自动入城”的产品约束。

验收标准：

- agent 建议能引用当前议题、已有观点和巡检结果。
- 用户点击采纳前，地图不会被自动修改。

### P3：沉浸式地图入口

1. 在地图内增加居民席位。
2. 在地图内增加巡城官塔。
3. 点击地图建筑展开来函或修缮令，逐步弱化右侧固定列表。

验收标准：

- 角色建议和巡检更像城邦的一部分，而不是普通侧边栏。
- 不降低当前操作效率。

## 风险与注意事项

- 美术资产较大，`hero-city-panorama` 构建后约 4MB，后续需要考虑压缩、懒加载或多尺寸版本。
- 当前没有数据持久化，用户误刷新会丢失本轮新增观点和道路。
- 没有测试套件，后续新增导出和持久化时需要补基础单元测试。
- 真实 AI 接入后，需要控制 agent 不直接替用户改图，否则会破坏当前“用户保留判断权”的核心体验。

## 关键假设

- 首版目标是验证交互闭环，不追求完整 SaaS 能力。
- 当前单机状态足以支撑产品方向演示。
- 报告导出是下一阶段最能提升可交付感的功能。
- 真实 agent 能力应在保留用户确认机制的前提下接入。
