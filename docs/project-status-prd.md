# 思维城邦项目进度与 PRD 概览

更新时间：2026-06-15

## 一句话介绍

思维城邦是一款古希腊城邦风格的思考 MVP。主页是一张可缩放、可拖拽的世界地图；核心体验发生在冲突议会：用户输入议题，居民在议会内发言和碰撞，用户采纳关键观点，巡城塔检查缺口，行动码头承接可执行命题，大图书馆归档本轮记录。

## 当前项目状态

结论：项目已经进入“可运行 MVP 原型”阶段，不是空项目，也不是纯静态展示页。

当前已经具备：

- 可本地启动的 Vite + React + TypeScript 应用。
- 可生产构建的 `dist/` 产物。
- 完整的主界面布局：主页世界地图、浮动立题台、浮动城邦服务、议会大厅主舞台。
- 8 个已定义建筑入口：冲突议会、大图书馆、居民区、假设码头、行动码头、沉思庭院、记忆墓园/废案馆、灯塔/巡城塔。
- 每个已定义建筑都有二级场景、用途说明、MVP 作用和首版状态面板。
- 本地 seed 数据驱动的默认体验。
- 基于用户输入的本地开局推演。
- 可点击观点建筑、地图内弹窗、道路关系创建。
- 多角色建议的“预览 -> 采纳入城”流程。
- 巡检规则：缺证据假设、未处理反驳、孤立观点、未闭环行动。
- 新手指引和 MVP 任务线。
- 项目内置美术资产、素材切片脚本和绿幕检测脚本。

当前还未具备：

- 真实 AI agent 接入。
- 用户账号、云端保存、多人协作。
- 数据库或本地持久化方案，除新手指引完成状态写入 `localStorage` 外，观点数据刷新后会回到 seed 状态。
- 报告导出功能。
- 结构化导入多条想法。
- 自动化单元测试、端到端测试。
- 每个非议会建筑的深层业务逻辑仍是轻占位，核心交互先集中在议会大厅。

## 目标用户

首版目标用户是需要把复杂问题“想清楚并推进下一步”的个人创作者、研究者、产品经理、独立开发者或知识工作者。

典型场景：

- 想整理一个还没想清楚的长期问题。
- 做产品方向判断，需要同时保留假设、证据、反对意见和行动。
- 需要把 AI 生成内容转化为自己的判断结构，而不是只收藏答案。
- 想把一堆零散想法收束成下一步实验。

## 产品定位

思维城邦不是传统笔记工具，也不是普通思维导图。它更像一个面向议题的“推理工作台”：

- 笔记工具偏记录，思维城邦偏推进。
- 思维导图偏层级，思维城邦偏论证关系。
- AI 问答偏答案，思维城邦偏保留判断过程。
- 看板工具偏任务，思维城邦偏从观点到行动的闭环。

## MVP 用户流程

1. 用户打开城邦主页，看到唯一核心入口“冲突议会”。
2. 用户点击冲突议会，进入议会大厅。
3. 用户输入或确认议题，点击召开第一轮圆桌。
4. 居民提出证据、反驳、真实场景和最小行动。
5. 用户采纳关键观点，采纳内容沉淀为本轮城市记录。
6. 巡城塔检查缺口：缺证据、未回应反驳、行动未回流。
7. 行动码头承接可执行命题，等待远航后的结果回流。
8. 大图书馆归档报告、行动计划和圆桌记录。
9. 用户返回主页，看到本轮沉淀统计，并可进入其他建筑理解其闭环职责。

## 当前功能清单

### 立题台

- 输入当前议题。
- 点击“开局推演”后生成新一轮地图。
- 空输入时回退到默认议题。

### 建筑工坊

- 新建观点。
- 支持五类观点：问题、假设、证据、反驳、行动。
- 根据类型自动落入对应城区。

### 城邦主页

- 展示古希腊城邦世界地图。
- 只显示 8 个已定义建筑入口。
- 支持拖拽、缩放、比例尺和重置视角。
- 主页第一视觉只回答“点哪里开始”。

### 建筑二级场景

- 每个建筑有独立 panorama。
- 每个建筑说明它在议题闭环中负责哪一段。
- 除冲突议会外，其他建筑第一版只做清晰入口和状态面板。

### 道路关系

支持五类关系：

- 支持
- 冲突
- 依赖
- 延伸
- 回流

### 角色席位

当前用本地 seed 模拟四类 agent：

- 实践者：补充工作流和现实证据。
- 研究者：提出结构化判断和理论假设。
- 怀疑者：提出反例、风险和约束。
- 执行者：收束为可操作下一步。

### 巡城官令

当前只提示问题，不自动修复：

- 假设缺少证据支撑。
- 反驳尚未进入议程。
- 存在孤立建筑。
- 行动还没有回流证据。

## 关键文件说明

- `src/App.tsx`：应用主状态，包括议题、观点、道路、选中节点、角色建议采纳状态和新手指引状态。
- `src/data/seed.ts`：默认议题、城区配置、初始观点、初始道路、角色建议。
- `src/lib/opening.ts`：根据用户议题生成第一批观点和初始道路。
- `src/lib/review.ts`：巡检规则。
- `src/components/CityMap.tsx`：地图、建筑和道路渲染。
- `src/components/MapPopover.tsx`：建筑详情和角色建议预览。
- `src/components/IdeaPanel.tsx`：立题台、建筑工坊、左侧角色入口。
- `src/components/ReviewPanel.tsx`：右侧角色席位和巡城官令。
- `src/components/GuideOverlay.tsx`：首次进入新手引导。
- `scripts/check-green-artifacts.mjs`：检测正式美术资产是否残留明显绿幕像素。

## 下一阶段优先级

### P0：补齐 MVP 闭环

1. 增加“生成报告草案”按钮。
2. 报告包含当前议题、观点列表、道路关系、巡检问题、下一步行动。
3. 支持复制 Markdown 或下载 `.md`。

验收标准：

- 用户完成一轮地图整理后，可以直接拿走一份结构化报告。
- 报告不依赖后端即可生成。

### P1：增强输入与持久化

1. 支持多条零散想法导入。
2. 增加浏览器本地保存和恢复。
3. 支持重置当前城邦。

验收标准：

- 刷新页面后地图不丢失。
- 用户可以从一段多行文本生成多个候选观点。

### P2：真实 agent 化

1. 把本地角色建议替换或扩展为真实 AI 调用。
2. 每个 agent 根据当前地图上下文生成建议。
3. 保持“只预览，不自动入城”的产品约束。

验收标准：

- agent 建议能引用当前议题、已有观点和巡检结果。
- 用户点击采纳前，地图不会被自动修改。

### P3：建筑深层机制

1. 居民区生成日常 talk，并把高权重问题送往假设码头。
2. 行动码头接收行动返航结果，决定进入图书馆或废案馆。
3. 沉思庭院形成夜间札记和慢问题连接。

验收标准：

- 新建筑机制不分散议会大厅的核心主线。
- 每个建筑都能说明自己在闭环中负责的阶段。

## 规划边界

首版产品 UI 只显示 8 个已确定建筑。其他建筑灵感只记录在 PRD、roadmap 或世界观文档中，不进入 `cityBuildings`，也不在主页显示入口。新建筑进入产品前，必须先明确用途、二级 panorama、入口文案和首版交互。

## 风险与注意事项

- 美术资产较大，`hero-city-panorama` 构建后约 4MB，后续需要考虑压缩、懒加载或多尺寸版本。
- 当前没有数据持久化，用户误刷新会丢失本轮新增观点和道路。
- 没有测试套件，后续新增导出和持久化时需要补基础单元测试。
- 真实 AI 接入后，需要控制 agent 不直接替用户改图，否则会破坏当前“用户保留判断权”的核心体验。

## 关键假设

- 首版目标是验证交互闭环，不追求完整 SaaS 能力。
- 当前单机状态足以支撑产品方向演示。
- 报告导出是下一阶段最能提升可交付感的功能。
- 真实 agent 能力应在保留用户确认机制的前提下接入。
