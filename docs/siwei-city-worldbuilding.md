# 思维城邦世界观设定

更新时间：2026-06-15

## 时空定位

思维城邦是一座偏古希腊气质的思想城邦。它靠海而建，有议会、图书馆、码头、庭院、墓园和灯塔。城市不是用来展示装饰建筑，而是把一次复杂议题的思考闭环可视化：问题从城门进入，居民在议会争辩，行动从码头远航，失败和记录都会回到城里。

视觉关键词：

- 古希腊城邦、海港、石阶、圆形议会、图书馆、灯塔。
- 暖石色、羊皮纸、青金蓝屋顶、青铜器物、橄榄树。
- 游戏化世界地图，但操作语义清晰，不做复杂后台面板。

## 城邦制度

城邦只承认 8 个首版建筑。每个建筑负责一次议题闭环中的一段工作。

| 建筑 | 城邦职责 | 产品职责 |
| --- | --- | --- |
| 冲突议会 | 公民围坐争辩，决定哪些观点可以入城 | 核心交互：圆桌讨论、观点碰撞、采纳 |
| 大图书馆 | 收藏议会卷轴和历史版本 | 归档报告、行动计划、圆桌记录 |
| 居民区 | 居民生活、闲谈、形成日常灵感 | 展示居民 prompt、人设和日常 talk 入口 |
| 假设码头 | 新问题从海上入港，在这里称重 | 从日常交流中筛选值得上会的问题 |
| 行动码头 | 已完成命题从这里远航，归来时带回结果 | 行动阶段、阶段性结果、回流证据 |
| 沉思庭院 | 慢问题和夜间札记暂存于此 | 暂存未连接、未闭环、需要慢思考的问题 |
| 记忆墓园 / 废案馆 | 失败行动和过期判断被安放在这里 | 保存放弃假设、失败行动、过期判断 |
| 灯塔 / 巡城塔 | 城市结构巡检和远航指引 | 诊断未闭环议题、未回流行动、结构缺口 |

## MVP 主线

```text
城邦主页
  -> 点击冲突议会
  -> 进入议会大厅
  -> 召开第一轮圆桌
  -> 居民提出观点
  -> 用户采纳关键观点
  -> 巡城塔检查缺口
  -> 行动码头接收可执行命题
  -> 大图书馆归档本轮记录
  -> 返回主页看到本轮已沉淀
```

首页只回答：点哪里开始。  
议会只回答：这轮讨论下一步做什么。  
其他建筑只回答：它在议题闭环中负责哪一段。

## 居民与议会

居民不是普通角色卡，而是 agent prompt 的人格化表达。

- 证据制图师：补证据地形，区分轶事、案例、数据和指标。
- 边界怀疑者：寻找失败边界、沉默相关方和反例。
- 现场民族志员：把抽象议题还原到真实使用场景。
- 推进执行官：把观点压成最小可逆行动。
- 巡城官：不替用户做决定，只指出结构缺口。
- 卷轴官：把本轮讨论整理成可带走的文档。

议会的产品边界是：居民可以发言，用户决定是否采纳。只有采纳后的观点才会成为城市沉淀。

## 建筑扩展边界

首版主页只显示 8 个已定义建筑。其他灵感、候选建筑、风土人情都应该先进入 PRD、roadmap 或设定文档，等用途、MVP 职责、二级场景和首版交互都明确之后，再进入产品 UI。

候选建筑进入产品前必须回答：

1. 它在一次议题闭环中负责哪一段？
2. 用户点击它后 5 秒内能做什么？
3. 它和议会、大图书馆、码头、巡城塔的关系是什么？
4. 它需要新的 panorama，还是可以归入已有建筑？

## 远航行动

“行动”在世界观里不是任务勾选，而是从行动码头出发的一次远航。

- 出航：议会已形成最小行动和回看指标。
- 航行：用户在真实世界执行。
- 返航：带回阶段性结果、证据或失败原因。
- 归档：成功经验进入图书馆，失败或过期判断进入废案馆。

这个隐喻让行动从“待办”变成“带证据回城”的循环。
